# 15. パフォーマンス最適化システム（データ分析）

YouTube Studio のデータから、**何が効いているか（勝ちパターン）** と **何を直すべきか（弱い動画）** を毎週・毎月の決まった手順で見つけ、次の動画と既存の動画に反映するための仕組みです。

| 構成 | ファイル |
|-----|---------|
| 分析の考え方・指標の読み方・レビュー手順 | 本ファイル |
| 動画ごとのデータ記録表 | [`templates/video-performance.csv`](templates/video-performance.csv) |
| 自動分析スクリプト（勝ち・弱い動画の判定、属性別分析） | [`tools/analyze_videos.py`](tools/analyze_videos.py) |
| スクリプトの出力例（架空データ） | [`tools/sample-report.md`](tools/sample-report.md) |
| 週次・月次レビューのテンプレート | [`templates/weekly-review.md`](templates/weekly-review.md)、[`templates/monthly-review.md`](templates/monthly-review.md) |

> 指標の定義と画面の名前は YouTube Studio の更新で変わることがあります。目安の数値は一般的な傾向で、**最も信頼できる比較対象は自分のチャンネルの過去の動画**です。

---

## 1. 指標の全体像：何のために何を見るか

### 最終目標と、それを動かす指標

```
                    ┌─ インプレッション（表示された回数）
         視聴回数 ──┤
                    └─ CTR（表示からクリックされた割合）
総再生時間 ─┤
         平均視聴時間 ── 視聴者維持率（どこまで見られたか）

登録者増 ── 視聴回数 × 登録率（1,000回視聴あたりの登録者増）

収益 ── 視聴回数 × RPM（1,000回視聴あたりの収益）＋ 動画外の収益（アフィリエイト・商品など）
```

| 層 | 指標 | 役割 |
|---|------|------|
| **最終目標** | 総再生時間、登録者増、収益 | チャンネルが成長しているか |
| **動画の強さ** | インプレッション、CTR、平均視聴時間、平均再生率、維持率グラフ | 個々の動画が推薦されるか |
| **関係の深さ** | 登録率、リピーター、エンゲージメント、終了画面 CTR | 視聴者がファンになっているか |
| **見つけられ方** | トラフィックソース | どの経路で成長しているか |

**原則：最終目標の数字は「結果」なので直接は動かせません。** 動かせるのは、企画・パッケージ（サムネとタイトル）・構成・CTA で、それが「動画の強さ」「関係の深さ」の指標に表れます。分析は常に「どの指標が弱いか → どの制作工程を直すか」に結びつけます。

## 2. 指標別の読み方

### 2-1. インプレッション
| 項目 | 内容 |
|-----|------|
| 定義 | YouTube 内でサムネイルが表示された回数（外部サイトや一部の表示は含まない） |
| 場所 | アナリティクス → リーチ |
| 何が分かるか | 推薦システムが、その動画を「どれだけの人に試しに見せているか」 |
| 読み方 | 公開後に増え続けている＝初期の視聴者が満足し、より広く表示されている。早く止まる＝初期の反応（CTR・維持率）が通常範囲より弱い |
| 注意 | インプレッションそのものは制作で直接上げられない。**CTR と維持率の結果として増える** |

### 2-2. インプレッションのクリック率（CTR）
| 項目 | 内容 |
|-----|------|
| 定義 | インプレッションのうち、クリックして視聴した割合 |
| 目安 | 多くのチャンネルで2〜10%。教育系では4〜6%前後がよく見られる |
| 何が分かるか | サムネとタイトルの強さ、視聴者の関心との一致 |
| 注意1 | **インプレッションが増えると CTR は下がるのが普通。** 登録者や関心の高い人の次に、関心の薄い人へ表示が広がるため |
| 注意2 | 流入経路で CTR は大きく違う（検索は高く、ホーム画面は低くなりやすい）。経路別に見る |
| 注意3 | 公開直後の CTR は登録者の反応で高く出やすい。**7日間**で比較する |

### 2-3. 平均視聴時間と平均再生率
| 項目 | 内容 |
|-----|------|
| 平均視聴時間 | 1回の視聴で見られた平均の時間 |
| 平均再生率 | 動画の長さに対して、平均でどこまで見られたか（%） |
| 目安 | 8〜12分の動画で平均再生率35〜50% |
| 読み方 | **長さの違う動画の比較には平均再生率、総再生時間への貢献を見るには平均視聴時間** |
| 注意 | 長い動画ほど平均再生率は下がる。「12分で40%（約4.8分）」は「6分で60%（約3.6分）」より総再生時間に貢献している |

### 2-4. 視聴者維持率グラフ
動画のどの時点で何%の視聴者が残っているかを示すグラフです。**改善のヒントが最も多い指標**です。

| 見る場所 | 意味 | 目安・判断 |
|---------|------|----------|
| **最初の30秒** | 冒頭で離脱した割合 | 65〜75%以上残っているか。低い＝サムネ・タイトルの約束と冒頭がズレている |
| **緩やかな下り** | 時間とともに少しずつ離脱 | 自然な形。傾きが急なら全体のテンポ不足 |
| **急な落ち込み（崖）** | その場面で多くの人が離脱 | その直前の内容を確認（脱線・長い説明・宣伝・解決済みの感覚） |
| **盛り上がり（山）** | 巻き戻し・繰り返し視聴 | 価値が高い場面、または分かりにくい場面。Shorts の素材候補 |
| **最後の急落** | 「終わり」を感じて離脱 | まとめ・挨拶を短く、最後の価値を最後まで残す |

**YouTube Studio の「主な瞬間」**（イントロ、最も見られた部分、急上昇、急降下）を使うと、注目すべき場面がすぐに分かります。

#### 維持率グラフの分析手順（1本10分）
1. 最初の30秒の維持率を記録し、自分の過去動画の中央値と比べる
2. 最大の「崖」を1つ見つけ、その場面を再生して原因を1行で書く
3. 「山」を1つ見つけ、Shorts の素材にできるか判断する
4. 学びを [`04-retention-framework.md`](04-retention-framework.md) の改善ループに記録する

### 2-5. 登録率（サブスクライバー変換率）
| 項目 | 内容 |
|-----|------|
| 計算 | 動画からの登録者増 ÷ 視聴回数 × 1,000（＝1,000回視聴あたりの登録者増） |
| 場所 | 動画ごとのアナリティクス → 視聴者（登録者の増減） |
| 目安 | 長尺で5〜15人。Shorts は長尺より低いのが普通 |
| 読み方 | 視聴回数が多いのに登録率が低い＝動画は面白いが「チャンネルの約束」が伝わっていない、または一度きりのテーマ |
| 改善 | 中盤 CTA の位置と言い方、シリーズ化、最後に次の動画へ送る（[`12`](12-algorithm-growth-strategy.md) 6章） |

### 2-6. トラフィックソース
| 経路 | 多い時の意味 | 伸ばす方法 |
|-----|------------|----------|
| YouTube 検索 | 検索需要に合っている。長期的に再生が続く | タイトル前半のキーワード、チャプター、説明文 |
| ブラウジング機能（ホーム） | 推薦システムに評価されている | 好奇心を引く企画、CTR と満足度 |
| 関連動画 | 他の動画とつながっている | 競合テーマの別角度、シリーズ、終了画面 |
| Shorts フィード | Shorts から見つけられている | Shorts の冒頭と視聴率 |
| チャンネルページ・登録者 | 既存のファンに見られている | 登録者が期待する企画 |
| 外部 | SNS・ブログ・アプリから | 関心が一致する場所での共有 |

**検索で見られる動画の評価に注意**：検索型の動画は公開直後の伸びは小さくても、**数か月かけて再生が積み上がる**ことがあります。28日の数字だけで「弱い」と判断せず、**90日後の視聴回数の伸び**も確認します。

### 2-7. エンゲージメント
| 指標 | 計算 | 意味 |
|-----|------|------|
| 高評価率 | 高評価 ÷ 視聴回数 × 1,000 | 満足度の目安 |
| コメント率 | コメント ÷ 視聴回数 × 1,000 | 視聴者が参加したくなったか |
| 共有率 | 共有 ÷ 視聴回数 × 1,000 | 「人に見せたい」と思われたか。最も強いシグナルの一つ |
| 終了画面 CTR | 終了画面の要素のクリック ÷ 表示 | 次の動画への流れ |

分析スクリプトでは、**高評価×1＋コメント×2＋共有×3** を1,000回視聴あたりで計算した「エンゲージメント指標」を使っています（関与の強さに応じた重み）。

### 2-8. 収益
| 指標 | 内容 | 読み方 |
|-----|------|-------|
| RPM | 1,000回視聴あたりのクリエイターの実際の収益 | チャンネルの稼ぐ力。広告の入らない視聴も含めた数字 |
| 再生回数ベースの CPM | 広告が表示された再生1,000回あたりに広告主が払った額 | 広告主にとっての価値。テーマ・季節・視聴者層で変わる |
| 動画ごとの推定収益 | 動画が生んだ広告収益 | 長期的に稼ぐ動画（検索型）を見つける |
| **総合 RPM** | （広告＋アフィリエイト＋商品などの収益）÷ 視聴回数 × 1,000 | 本当の稼ぐ力。[`14`](14-monetization-system.md) 16章 |

**注意**：収益は「視聴回数の多さ」と「テーマの広告単価」の両方で決まります。RPM が高いテーマの動画が必ずしも良い動画ではありません。成長（視聴・登録）と収益の両方で評価します。

## 3. 比較のルール（間違った結論を避ける）

| ルール | 理由 |
|-------|------|
| **同じ期間で比べる**（公開後7日、28日、90日） | 公開からの日数が違う動画を比べると、古い動画が有利になる |
| **長尺と Shorts は別々に比べる** | 指標の水準も、評価の仕組みも違う |
| **平均ではなく中央値と比べる** | 1本の大ヒットに平均が引っ張られる |
| **長さの違う動画は平均再生率で比べる** | 平均視聴時間は長い動画ほど有利 |
| **1本の結果で判断しない**（3本以上で傾向を見る） | 1本の結果は偶然の影響が大きい |
| **一度に変えるのは1つ** | 何が効いたか分からなくなる |
| **季節を考慮する** | 年末年始・大型連休・年度初めは視聴行動や広告単価が変わる |
| **相関と原因を区別する** | 「顔ありサムネが伸びた」は、たまたまテーマが強かった可能性もある |

### YouTube Studio の便利な比較機能
- **公開直後の順位表示**：直近の動画と比べて、公開後の一定時間で何位かを表示する機能（「通常よりも高い」など）。初動の判断に使う
- **詳細モード**：期間・動画・指標を自由に選んで比較・書き出しができる。月次レビューで使う
- **比較モード**：期間同士（今月と先月など）を比較

## 4. 勝ちパターンの見つけ方

### 4-1. パフォーマンス指数で動画を順位づけする
個々の指標だけを見ると「CTR は高いが維持率は低い」など判断が割れます。そこで、複数の指標を1つの数字にまとめた **パフォーマンス指数** を使います。

**計算方法**（`tools/analyze_videos.py` で自動計算）
- 各指標を **チャンネルの中央値との比** にする（中央値と同じなら1.0）
- 重みを付けて平均する（加重幾何平均。極端な1指標に引っ張られにくい）

| 指標 | 長尺の重み | Shorts の重み |
|-----|----------|-------------|
| 視聴回数（28日） | 35% | 35% |
| 平均再生率 | 20% | 15% |
| CTR（7日） | 15% | ― |
| 視聴率（スワイプされなかった割合） | ― | 25% |
| 登録率（1,000回あたり） | 20% | 15% |
| エンゲージメント（1,000回あたり） | 10% | 10% |

**判定**：指数1.30以上＝勝ち、0.75以下＝弱い（5本以上ある場合は上位・下位20%も判定に使用）。
重みはチャンネルの目標で調整できます（例：収益化前は総再生時間を重視して視聴回数と平均再生率の重みを上げる）。

### 4-2. 動画に「属性」を付ける
勝ちパターンを見つけるには、動画ごとに **何を変えたか** を記録しておく必要があります。`video-performance.csv` の次の列を毎回埋めます。

| 属性 | 値の例 |
|-----|-------|
| カテゴリ | A：AI翻訳ラボ / B：仕事の英語テンプレ / C：直訳できない日本語 / D：AI×英語学習ハック / E：実践・視聴者参加 |
| 構成型 | 検証 / ランキング / 謎解き / ビフォーアフター |
| タイトル型 | 警告 / ランキング / 対決 / 実験 / 謎解き / 権威 |
| サムネ型 | 比較×○ / ロゴ全滅 / 採点表 / 驚き顔 / ランキング |
| フック型 | 結果見せ / 警告 / 常識の否定 / 賭け / 数字の約束 / 問いの保留 |

### 4-3. 属性別に比べる
スクリプトは、属性の値ごとにパフォーマンス指数の中央値を出します。
- **中央値1.2以上で3本以上** → 勝ちパターン候補。次の4週で優先して増やす
- **中央値0.85以下で3本以上** → 弱い。減らすか、別の要素と組み合わせて改善
- **3本未満** → 参考値。もう少し試してから判断

### 4-4. 勝ちパターンの確定と展開
1. 候補を見つけたら、**同じ型で次の2〜3本を作る**（他の要素はできるだけ変えない）
2. 2〜3本とも指数1.1以上なら「勝ちパターン」として確定し、[`10-production-system.md`](10-production-system.md) にルールとして追記
3. 確定した型でシリーズ化し、企画バンクで優先順位を上げる
4. **勝ちパターンも時間とともに弱くなる**（視聴者が慣れる）。3か月ごとに見直す

### 4-5. 外れ値（大ヒット）の分析
指数が2.0を超える動画、または視聴回数が中央値の3倍を超える動画は、特別に分析します。
- どの経路で伸びたか（ほとんどがブラウジングか関連動画のはず）
- どの外部の動画の関連動画として表示されたか（トラフィックソースの詳細）
- 新しい視聴者の割合（チャンネルの外に広がったか）
- 同じテーマで「別の角度」「続編」「より深い版」を作れるか

## 5. 弱い動画の改善方法

### 5-1. 診断の流れ
```
弱い動画を見つける（指数0.75以下）
        │
        ▼
CTR は中央値より低い？ ──はい──→ 維持率は良い？ ──はい──→【A】パッケージの問題
        │                           │
       いいえ                       いいえ ─────────────→【C】企画の問題
        │
        ▼
維持率は中央値より低い？ ──はい──→【B】中身・約束のズレ
        │
       いいえ
        │
        ▼
登録率・終了画面 CTR が低い？ ──はい──→【D】つながりの問題
        │
       いいえ → 【E】テーマの需要（視聴回数そのものが小さい）
```

### 5-2. タイプ別の改善策

| タイプ | 公開済みの動画でできること | 次の動画で直すこと |
|-------|------------------------|-----------------|
| **A パッケージ** | サムネを差し替え（テストと比較）→ 7日後に比較。改善しなければタイトルも変更 | サムネ3案、タイトル型の見直し |
| **B 中身・約束のズレ** | タイトル・サムネを中身に合わせる。YouTube Studio のエディタで冒頭の不要な部分をカット（カットのみ可能）。チャプターで見たい部分へ飛べるようにする | 冒頭3秒の約束回収、構成の並び順、リフック |
| **C 企画** | 説明文・チャプターを整え、検索で見つかるようにして残す。**削除はしない** | その型を減らす。テーマが良ければ別の角度で **リメイク**（新しい動画として） |
| **D つながり** | 終了画面・カードを、今最も強い動画に更新。固定コメントで関連動画を案内。再生リストに追加 | 中盤 CTA、最後の次の動画への誘導 |
| **E テーマの需要** | 関連する Shorts を作り、関連動画リンクで誘導 | 企画段階の需要確認（検索サジェスト・競合の外れ値） |

### 5-3. 改善の優先順位（どの動画から直すか）
直す価値が大きい順に並べます。

1. **インプレッションが多いのに CTR が低い動画**（サムネを変えるだけで視聴回数が増える可能性が最も高い）
2. **検索流入が多い動画**（説明文・チャプター・終了画面の改善が長期間効く）
3. **維持率は高いのにインプレッションが少ない動画**（パッケージを変えれば推薦される可能性）
4. **公開から90日以上経ち、ほとんど見られていない動画**（リメイク候補として企画バンクへ）

### 5-4. 改善の記録
改善した日と内容を `video-performance.csv` の「メモ」欄に書き、**変更前後の7日間** の CTR・視聴回数を比べます。1本ずつ、1つずつ変えます。

## 6. 週次レビュー（毎週日曜・30分）

テンプレート：[`templates/weekly-review.md`](templates/weekly-review.md)

### 目的
今週公開した動画の初動を確認し、**来週の動画で1つだけ変えること** を決める。

### 手順
| 時間 | 作業 |
|-----|------|
| 5分 | **データ記録**：先週公開した動画の7日間の指標と、28日経った動画の28日間の指標を `video-performance.csv` に入力 |
| 5分 | **チャンネル全体**：過去7日間の視聴回数・総再生時間・登録者増を前週と比較。YPP の進捗（登録者・総再生時間） |
| 10分 | **最新の動画**：CTR・平均再生率・30秒維持率を中央値と比較 → 診断表で状態を判定。維持率グラフの最大の崖と山を1つずつ |
| 5分 | **実験の結果**：先週の実験は成功基準を満たしたか → 採用 / 却下 / 再テスト |
| 5分 | **来週の決定**：実験を1つ、サムネを差し替える動画を1本（あれば）、コメントから企画バンクに追加するもの |

### 週次で見る指標（多すぎないように絞る）
- 長尺：CTR（7日）、平均再生率、30秒維持率、登録率
- Shorts：視聴率（スワイプされなかった割合）、視聴回数
- チャンネル：視聴回数、総再生時間、登録者増の前週比

### 週次でやらないこと
- 毎日数字を見て一喜一憂する（日曜にまとめて見る）
- 1本の結果で方針を大きく変える

## 7. 月次レビュー（毎月第1日曜・90分）

テンプレート：[`templates/monthly-review.md`](templates/monthly-review.md)

### 目的
1か月分のデータから **勝ちパターンと弱いパターン** を見つけ、来月の **コンテンツの配分** と **既存動画の改善リスト** を決める。

### 手順
| 時間 | 作業 |
|-----|------|
| 10分 | **分析スクリプトを実行**：`python3 tools/analyze_videos.py templates/video-performance.csv -o reports/2026-11.md` |
| 15分 | **チャンネル全体の推移**：視聴回数・総再生時間・登録者・収益の前月比。トラフィックソースの構成比の変化。新しい視聴者とリピーターの推移 |
| 20分 | **勝ちパターン**：属性別の分析から、増やす型を最大2つ決める。外れ値の動画を分析 |
| 15分 | **弱い動画**：診断の流れでタイプを判定し、改善する動画を3本選ぶ（優先順位は5-3） |
| 10分 | **Shorts**：視聴率の高い Shorts の共通点。Shorts から長尺・登録への貢献 |
| 10分 | **収益**：RPM・総合 RPM、収益源ごとの割合、リスト登録数 |
| 10分 | **来月の計画**：カテゴリの配分、増やす型・減らす型、改善する既存動画3本、来月の実験4つ |

### 月次で決めること（アウトプット）
1. 来月のカテゴリ配分（例：A 40% / B 30% / C 20% / D 10%）
2. 増やす型（最大2つ）と減らす型
3. 改善する既存動画3本と、それぞれの改善内容
4. 来月の4週分の実験（週1つ）
5. 学び（3行）を [`10-production-system.md`](10-production-system.md) などのルールに反映

## 8. 四半期レビュー（3か月ごと・2時間）

| 確認すること | 判断 |
|------------|------|
| チャンネルの約束と、実際に伸びている動画は一致しているか | ズレていれば、伸びている方向へポジショニングを調整 |
| カテゴリごとの3か月の成績 | 最下位のカテゴリを入れ替えるか |
| 勝ちパターンの鮮度 | 3か月前の勝ちパターンが今も勝っているか |
| 検索型の動画の90日後の伸び | 長期的に効いている検索テーマを増やす |
| 成長段階 | [`14-monetization-system.md`](14-monetization-system.md) の次の段階の収益源を導入するか |
| 目標との差 | YPP・登録者・収益の目標に対して、ペースは足りているか |

## 9. データの準備（初回のみ・30分）

1. `templates/video-performance.csv` をコピーし、チャンネル用のデータファイルにする（Google スプレッドシートで管理して CSV で書き出しても可）
2. YouTube Studio の **詳細モード** で、動画ごとの指標を確認する方法を覚える
   - 期間を「公開から7日」「28日」に合わせるには、動画ごとのアナリティクスで期間を指定
3. 公開済みの動画の属性（カテゴリ・構成型・タイトル型・サムネ型・フック型）を埋める
4. 分析スクリプトの動作確認：
   ```
   cd docs/youtube-os
   python3 tools/analyze_videos.py tools/sample-data.csv
   ```
   （Python 3 が入っていれば追加のインストールは不要）

### 記録の列
| 列 | 入力するタイミング |
|----|----------------|
| 動画ID〜尺 | 公開時 |
| インプレッション・CTR・視聴回数（7日） | 公開7日後 |
| 視聴回数（28日）〜推定収益 | 公開28日後 |
| Shorts 視聴率 | Shorts のみ。CTR・30秒維持率・流入の列は空欄 |
| メモ | 実験内容、改善の記録 |

## 10. 分析で陥りやすい失敗

| 失敗 | 対策 |
|-----|------|
| 数字を毎日見て、方針を頻繁に変える | 週1回、決まった手順で見る |
| CTR だけで判断する | CTR と維持率を必ずセットで見る |
| 少ない本数で勝ちパターンを決める | 3本以上で傾向を確認してから |
| 伸びなかった動画を削除する | 削除しても良いことはない。改善して残す |
| 大ヒット1本を真似して、型を変えすぎる | 外れ値は分析するが、確定は2〜3本の再現で |
| 自分の好きな企画だけデータを都合よく解釈する | 判定はスクリプトの基準で機械的に行い、解釈はその後 |
| 検索型の動画を28日で見限る | 90日後の伸びも見る |
| データを見るだけで行動しない | 毎回「来週変えること1つ」を必ず決める |
