# 13. AI活用 制作ワークフロー

長尺1本＋Shorts 3本＋他プラットフォーム展開を、**週約6時間**で回すための制作システムです（AIなしの想定は約9〜10時間）。
各工程のプロンプトは [`templates/ai-prompts.md`](templates/ai-prompts.md)、品質チェックは本ファイルの10章にあります。

> **ツールについて**：ここで挙げるツールは2026年時点で広く使われているものです。機能・料金・日本語対応・利用規約は頻繁に変わるため、導入前に公式サイトで確認してください。
> 特定のツールに依存しないよう、各工程は「何をするか」を先に書き、ツールは置き換え可能な部品として扱っています。

---

## 1. 基本方針：AIに任せること・人がやること

| AIに任せる（下書き・作業） | 人がやる（判断・品質） |
|--------------------------|---------------------|
| キーワード・競合動画の整理 | どの企画をやるかの決定 |
| タイトル・サムネ案の大量出し | 最終案の選定 |
| 台本の構成案・初稿 | 自分の経験・意見・検証結果を入れる、声に出して直す |
| 文字起こし・字幕の生成 | 字幕と英文の正確さの確認 |
| 無音・言い間違いのカット候補 | 間・テンポの最終判断 |
| 切り抜き候補の抽出 | どこを切るかの決定 |
| 説明文・チャプター・SNS投稿文の下書き | 事実確認・トーン調整 |
| アナリティクスの要約 | 来週の実験を決める |

### 必ず守るルール（収益化とチャンネルの信頼に直結）
1. **自分の解説・判断・検証を必ず入れる。** YouTube パートナープログラムでは、大量生産・繰り返しの多い「独自性の低いコンテンツ」は収益化の対象外です。AIの文章をAI音声で読み上げるだけの動画は避けてください。
2. **AIが書いた事実・英文は必ず確認する。** このチャンネルの価値は「正しい英語」。AIの誤りをそのまま出すと信頼を失います。
3. **リアルに見える合成・改変コンテンツは開示する。** 実在の人物の声や映像を合成したもの、現実の出来事に見える生成映像などは、アップロード時に「改変または合成されたコンテンツ」の開示が必要です（YouTube の規定。対象範囲は公式ヘルプで確認）。
4. **著作権を確認する。** BGM・効果音・画像は商用利用可のものだけ。他社ツールの画面は検証・批評の範囲で使用する。
5. **AIツールに入れる情報に注意する。** 視聴者から届いた英文（個人情報・社名を含む可能性）は、匿名化してから入れる。

### ツール選びの基準
- **日本語の精度**：文字起こし・字幕・切り抜きツールは、必ず自分の動画で試してから決める
- **商用利用の可否**：編集ソフト・素材・AI生成物の利用規約で、YouTube での収益化が認められているか確認
- **書き出しの自由**：特定のツールでしか開けない形式に依存しない（素材は常に元ファイルで保存）

## 4. 工程別ワークフロー

各工程は「入力 → AIの作業 → 人の作業 → 出力」の順に書いています。

### 4-1. トピックリサーチ・企画（月曜 40分）

| 段階 | 内容 |
|-----|------|
| 入力 | 企画バンク（`templates/video-brief.md`）、先週のコメント、YouTube 検索サジェスト、競合の最新・人気動画のタイトル一覧 |
| AI | ①コメントと競合タイトルを貼り、視聴者の悩みを分類・頻度順に整理（プロンプト R1）②企画候補を需要・差別化・制作しやすさで採点（R2）③1つの企画につき「5つの角度」を出す（R3） |
| 人 | 採点上位3つから1つを選ぶ。**自分が実際に検証できるか、語れる経験があるか** で最終判断 |
| 出力 | 企画ブリーフ（企画名・ターゲット・約束・角度） |

**コツ**：AIに「流行りそうな企画を出して」と頼むと、どこにでもある企画しか出ません。**実際のコメント・検索サジェスト・競合データを必ず貼り付けて**から考えさせます。

### 4-2. パッケージ（タイトル・サムネ案）（月曜 20分）

| 段階 | 内容 |
|-----|------|
| AI | タイトルを型ごとに20案（P1）、サムネの構図案を5つ（P2） |
| 人 | タイトル5案に絞る → 「前半15文字で意味が通じるか」「動画で必ず回収できるか」で3案に |
| 出力 | タイトル3案、サムネ構図3案 |

### 4-3. 台本（火曜 60分）

| 段階 | 内容 |
|-----|------|
| AI | ①企画ブリーフから構成案を作る（S1：型A〜Dの指定、項目の並び順を弱→強に）②構成案から台本の初稿（S2：2列形式、1文40文字以内）③台本を「視聴者が離脱しそうな箇所」の観点で批評（S3） |
| 人 | **検証結果・自分の経験・意見を書き足す**（ここがチャンネルの価値）。英文はすべて自分で確認。声に出して読み、言いにくい所を直し、20%削る |
| 出力 | 完成台本（話す内容＋画面指示） |

**台本で人が必ず書く部分**：冒頭の「なぜ自分が語れるか」、AIツールの実際の出力（その場で取得）、「これは意外だった」という自分の反応、結論の判断。

### 4-4. ボイスオーバー（火曜 30分）

| 段階 | 内容 |
|-----|------|
| 準備 | 静かな部屋、布の多い場所（クローゼットの前など）。マイクは口から10〜15cm |
| 収録 | 段落ごとに録る。間違えたら3秒空けてその段落を頭から言い直す（後で編集しやすい） |
| AI | ノイズ除去・音声補正（Adobe Podcast の音声補正など）。補正しすぎると不自然になるので強さは控えめに |
| 人 | 補正後の音声を確認。声のトーンが段落ごとにバラバラでないか |
| 出力 | ナレーション音声（WAV） |

**AIナレーションについて**：顔出し・声出しができない場合の選択肢ですが、教育系では「人の声」の方が信頼が積み上がります。使う場合は、①自分の声のクローンを ②言い直しや小さな修正に限定して使うのが安全です。他人の声を無断でクローンすることは絶対に避けてください。

### 4-5. 撮影・画面収録（火曜 20分）

| 素材 | やり方 |
|-----|-------|
| AIツールの画面 | OBS で 1920×1080 で録画。ブラウザの拡大率を 125〜150% にして文字を大きく。**入力から出力までを一連で録る**（検証の証拠になる） |
| 顔出し（する場合） | スマホを目の高さに、窓かリングライトを顔の正面に。冒頭とリアクション部分だけでも効果が高い |
| 自作アプリの画面 | スマホの画面収録。通知はオフに |
| 素材の命名 | `日付_動画番号_素材種類_連番`（例：`20261021_v001_screen_01.mp4`） |

### 4-6. 編集（水〜木 90分）

| 段階 | 内容 |
|-----|------|
| ①粗編集 | 文字起こしベースの編集機能（Premiere Pro、Descript、Vrew など）で、言い間違い・無音・「えー」を文字を消す感覚で削除 |
| ②構成 | 台本の画面指示どおりに画面収録・図解を配置 |
| ③テロップ | 自動字幕を生成 → **英文と固有名詞を必ず手で直す** → チャンネル共通のテロップテンプレを適用 |
| ④演出 | 3〜6秒ごとの視覚変化、誤り＝赤×・ブブー、正解＝緑○・ピンポン、画面隅の進捗表示（「3/9」） |
| ⑤音 | BGM は声より −20dB 前後、話の区切りでだけ変化。最終の音量は YouTube の基準に近い −14 LUFS 前後を目安に |
| ⑥書き出し | 1920×1080、30fps、H.264、高ビットレート |

**時短のカギは「テンプレ化」**：テロップのスタイル、効果音、オープニングの採点表、進捗表示、終了画面の配置を、編集ソフトのテンプレート（プリセット）として保存し、毎回使い回す。

### 4-7. サムネイル（木曜 25分）

| 段階 | 内容 |
|-----|------|
| テンプレ | Canva/Figma に5つの型（比較×○、ロゴ全滅、採点表、驚き顔＋1行、ランキング）を作っておく |
| AI | 顔写真の背景除去、背景の生成・拡張。**サムネの文字や英文はAIに生成させず、自分で入れる**（誤字防止） |
| 人 | 3案を作成 → YouTube の検索結果画面のスクリーンショットに並べて、スマホサイズで見え方を確認 |
| 出力 | 1280×720、2MB未満、3案（テストと比較用） |

### 4-8. 公開（水曜 15分）

| 段階 | 内容 |
|-----|------|
| AI | 台本から説明文の下書き・チャプター・固定コメント案を作成（U1） |
| 人 | 説明文の最初の2行を確認（検索語と価値）、チャプターの時間を実際の動画で確認、リンクを入れる |
| 設定 | タイトル、サムネ3案（テストと比較）、字幕（日本語＋英語）、終了画面、カード、再生リスト、「改変または合成されたコンテンツ」の該当確認、予約公開 |
| 出力 | 予約済みの動画 |

**英語字幕**：自作の日英翻訳アプリで字幕を英訳 → 人が確認 → 英語字幕としてアップロード。英語話者の視聴者が見つけてくれる可能性が上がり、アプリの実践的な使用例にもなります。

### 4-9. アナリティクスレビュー（日曜 25分）

| 段階 | 内容 |
|-----|------|
| 入力 | YouTube Studio から、直近の動画の指標（CTR、平均再生率、30秒維持率、トラフィックソース、登録者増）を `kpi-tracker.csv` に記録 |
| AI | CSV を貼り付け、「前の4本と比べて何が違うか」「考えられる理由」「次に試す実験の候補3つ」を出させる（A1） |
| 人 | 維持率グラフは自分の目で見る（AIは画像の解釈を間違えることがある）。実験を1つだけ決める |
| 出力 | 今週の学び（1行）、来週の実験（1つ） |

判断の基準は [`12-algorithm-growth-strategy.md`](12-algorithm-growth-strategy.md) 3章の診断表を使います。

## 5. Shorts と他プラットフォームへの展開

### 5-1. 1本の長尺から作れるもの（「1→10」展開）

| # | 作るもの | 元になる部分 | 出す場所 |
|---|---------|-------------|---------|
| 1〜3 | 縦型ショート動画 3本 | 一番驚く結果、一番使える答え、ビフォーアフター | YouTube Shorts、TikTok、Instagram Reels |
| 4 | 比較画像（Before/After）1枚 | 誤訳と正解の対比 | X、Threads、Instagram 投稿 |
| 5 | 早見表・カルーセル（5〜8枚） | 使い分け表 | Instagram、LinkedIn |
| 6 | 短い文章投稿 | 動画の要点を3つ | X、Threads、LinkedIn |
| 7 | ブログ記事 | 台本を読み物に再構成 | note、自分のブログ（検索流入） |
| 8 | メール/LINE 配信 | 早見表＋動画リンク | リードマグネットの登録者 |
| 9 | コミュニティ投稿（クイズ） | 動画の問い | YouTube コミュニティ |
| 10 | 英語版の短い動画（将来） | 「直訳できない日本語」系 | 英語サブチャンネル、TikTok |

### 5-2. 縦型動画の作り方（金曜 45分で3本）
1. **候補抽出（AI）**：台本または文字起こしを渡し、「30秒以内で完結し、最初の2秒で問いが立つ部分」を5つ出させる（SH1）
2. **選定（人）**：5つから3つを選ぶ
3. **切り出し**：編集ソフトで 9:16 にリフレーム（自動リフレーム機能があれば使う）。字幕は画面の中央やや上に、UIに隠れない位置に
4. **冒頭の差し替え**：長尺の途中から切ると冒頭が弱いので、**最初の2秒に問いのテロップを追加**（例：「メールの1行目にこれ書いてませんか？」）
5. **最後のループ**：最後の一言を冒頭の問いにつなげる
6. **書き出し**：1080×1920、30fps。**ロゴや透かしの入らない元ファイル**を各プラットフォームに上げる

### 5-3. プラットフォーム別の調整

| 項目 | YouTube Shorts | TikTok | Instagram Reels |
|-----|---------------|--------|----------------|
| 主な役割 | 長尺とチャンネルへの入口 | 新しい層への拡散 | 既存フォロワーとの関係、保存されるコンテンツ |
| 長さの目安 | 20〜45秒 | 20〜60秒 | 15〜45秒 |
| 冒頭 | 問いを文字で | 問いを声と文字で、より口語的に | 見た目の分かりやすさ重視 |
| 文字の位置 | 下部のUIを避ける | 右側・下部のUIを避ける | 下部のキャプションを避ける |
| 導線 | 関連動画リンクで長尺へ | プロフィールのリンク | プロフィールのリンク、保存を促す |
| キャプション | 短く、タイトル的に | 検索されやすい言葉を含める（TikTok内検索） | 要点＋ハッシュタグ3〜5個 |
| 音 | 声中心、BGM小さめ | アプリ内の音源も検討（商用利用の可否を確認） | アプリ内の音源も検討 |
| 注意 | ― | 他アプリのロゴが入った動画は避ける | 他アプリのロゴ・透かしが入った動画は表示が減るとされる |

※各プラットフォームの長さの上限や仕様は変わるため、投稿時に確認してください。

### 5-4. 展開のルール
- **同じ動画をそのまま全部に出すのはOK、ただし透かしなしの元ファイルで**
- **キャプションと冒頭のテロップは、プラットフォームごとに少し変える**（AIで下書き：RP1）
- **反応の良いものを長尺の企画に戻す**：TikTok や Reels で伸びたテーマは、長尺で深掘りする価値がある
- **すべてのプラットフォームを同時に始めない**：最初の3か月は YouTube（長尺＋Shorts）に集中し、余力があれば TikTok、次に Instagram と1つずつ追加する

## 7. フォルダ構成と命名ルール

```
YouTube/
├── 00_templates/          編集プリセット、サムネテンプレ、効果音、BGM、終了画面
├── 01_ideas/              企画バンク、リサーチメモ
├── 02_production/
│   └── v001_otsukaresama/
│       ├── brief.md       企画ブリーフ
│       ├── script.md      台本
│       ├── raw/           元素材（音声・画面・顔）
│       ├── project/       編集プロジェクトファイル
│       ├── export/        書き出し（長尺・Shorts）
│       ├── thumbnail/     サムネ3案と元データ
│       └── publish.md     タイトル・説明文・チャプター・公開日
```

## 9. AI活用の失敗パターンと対策

| 失敗 | 何が起きるか | 対策 |
|-----|------------|------|
| AIの台本をそのまま読む | どのチャンネルとも同じ内容になり、独自性がなくなる。収益化審査でも不利 | 検証結果・経験・意見を必ず書き足す |
| AIの英文を確認せずに出す | 誤った英語を教えてしまい、信頼を失う | 英文はすべて人が確認。不安なものは英語話者か辞書・コーパスで確認 |
| AIツールの出力を「想定」で作る | 実際の検証ではなくなる | 必ずその日に実際に取得し、取得日を画面に出す |
| ツールを増やしすぎる | 学習と管理に時間を取られる | 1工程1ツール。新しいツールは1か月に1つまで試す |
| 自動切り抜きをそのまま出す | 冒頭が弱く、文脈が分からない Shorts になる | 冒頭の問いのテロップを必ず追加 |
| 全SNSに同時に手を広げる | どれも中途半端になり、YouTube の質が下がる | 3か月は YouTube に集中 |

## 10. 品質管理チェックリスト

### A. 企画・台本
- [ ] 企画がコンセプトの4テストを通っている（[`10`](10-production-system.md) 2章）
- [ ] 台本に、自分の検証結果・経験・意見が入っている
- [ ] 英文はすべて人が確認した（意味・自然さ・スペル）
- [ ] 事実（ツールの仕様、文化の説明など）を一次情報で確認した
- [ ] 冒頭3秒でタイトルの約束を回収している
- [ ] オープンループを開き、必ず回収している

### B. 音声・映像
- [ ] 声が聞き取りやすい（ノイズ、反響、音割れがない）
- [ ] BGM が声の邪魔をしていない
- [ ] 画面の文字がスマホで読める大きさ
- [ ] 個人情報（メールアドレス、社名、通知、ブラウザのタブ）が映っていない
- [ ] AIツールの出力画面に取得日が表示されている

### C. 編集
- [ ] 字幕の誤字・英文の誤りがない（特に固有名詞と英文）
- [ ] 3〜6秒ごとに視覚の変化がある
- [ ] 不要な間・言い間違いが残っていない
- [ ] 音量が全体で安定している
- [ ] 最後は締めの挨拶なしで次の動画へつないでいる

### D. サムネ・公開
- [ ] サムネ3案をスマホサイズで確認した
- [ ] サムネの文字に誤字がない（AIに文字を作らせていない）
- [ ] タイトルとサムネで同じ言葉を繰り返していない
- [ ] 説明文の最初の2行に検索語と価値がある
- [ ] チャプターの時間が正しい（最初は 00:00）
- [ ] 英語字幕を確認してアップロードした
- [ ] 終了画面・カード・再生リストを設定した
- [ ] 「改変または合成されたコンテンツ」の開示が必要か確認した
- [ ] BGM・素材のライセンスを確認した
- [ ] アフィリエイトリンクがある場合「PR」表記を入れた

### E. Shorts・他プラットフォーム
- [ ] 最初の2秒で問いが立っている
- [ ] 字幕がアプリのUIに隠れていない
- [ ] 透かしのない元ファイルを使っている
- [ ] プラットフォームごとにキャプションを調整した
- [ ] 長尺・プロフィールへの導線がある

- [ ] 7日後に結果を `kpi-tracker.csv` に記録し、学びを1行書いた
